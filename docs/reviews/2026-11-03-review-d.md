# Review D — Claude Sonnet 5.5, at 859d180, before the deploy of delivery A

Brief: the review a reviewer gives who wasn't in the room, before the owner deploys delivery A (since the last deploy, 61e8db0: the guidance rewrite, the after-upload flow, the landing page). What fails the product's purpose, a situation or a constraint; what breaks in front of a class; what a stranger could do; where decisions and code disagree; other surprises; what couldn't be established without real devices. The implementers pointed at `entry()`, `takeRole()`, the swap op, `checkTeacher`/`deviceKey` and how the address reaches the instance, `enter()` in `play.ts`, the translations and their forms of address, step 1's and the own-copy line's wording, and the BUDGET binding. The live site was not fetched. Written by the reviewer to this file; no commit. The working tree had `docs/free-tier-check.md` modified (not by me).

---

**Verdict.** For a teacher with one class the delivery holds: both typechecks clean, 99 of 99 tests, `simulate.mjs` OK in all three modes on a stack of my own, and my headless walks through the real pages threw no page errors. I found no data loss and no crash. Four things I would want the owner to decide before the deploy, in this order:

1. The limit on wrong teacher codes does not do what the design says. A pause of about ten seconds resets it, so a script that knows a class code gets the Remote of a quiz (and can delete it) in minutes, not "hours" (#1).
2. The wall prints the teacher code in its bar whenever the Remote is away, and a device that types it takes the vacant Remote without a question. A child can lock the teacher's phone out (#2).
3. After "Again with another class" the wall's new lobby at once says the school network may be blocking the site (#3).
4. A steering phone whose tab was closed is told "already has a screen … and one that steers" for about 50 seconds (#4).

**Findings, most important first**

**1. The wrong-teacher-code limit resets after an idle spell (verified locally; production timing not established).**
- `guesses` and `salt` live in the instance's memory (`instance.ts:154`, `:156`). An idle Durable Object leaves memory, and the counter goes with it.
- `evict.mjs`: four wrong codes, a pause, then more. With a 9 s pause the fifth wrong code was refused as locked; with 12, 25 and 45 s the counter had started again and the lock came only at the ninth. Locally that makes the idle threshold about 10 s. Cloudflare's eviction is of that order; I could not check it there.
- So a script that sends a few guesses every 15 s tries all 100 endings in about six minutes. Without WebSockets open the instance is idle between guesses, and during a lesson its hibernating sockets don't keep it in memory either (their pings are answered without waking it), so I expect the same.
- `deviceKey` hashes the whole address (`:382`). A visitor with an IPv6 /64 has 2^64 of them, and 500 addresses (`GUESS_KEYS`) push every other device's lock out. Reasoned, not run.
- The design says "guessing the two digits takes a script that knows the class code hours, not seconds" (`docs/after-upload.md` §4), and the decision entry says only that an evicted instance "forgets its counts".
- What it gives. The class code is on the QR code and read aloud; `/api/join` has no limit, so a script can also sweep live five-digit codes. Entry is `ask` in the usual state (one tab does both) and the vacant role whenever a tab is away, so whoever guesses the digits becomes the Remote or the wall of that quiz. The quiz lives 48 hours, and most of that time nobody holds both tabs. As the Remote or a steering wall the visitor sees every question with its key and can send `endInstance` (`:975`): the "vandalise another class's quiz" the backlog calls realistic.
- Until now, once students were in, the class code reached no teacher role. That protection went with the gate, on the strength of this limit.
- Options, for the owner: keep the counter in the instance's storage, written only on a wrong guess; or more than two digits; or key IPv6 by its /64. I have not tried any.

**2. The teacher code on the projector, and a silent take of the vacant Remote (verified).**
- `screen.ts:810`: while the wall steers and the Remote is "away" (45 s without a ping: a pocketed phone, a closed tab), the bar reads "Remote gone: type 97990 17 on another device". Probe 1 shows it in front of the class.
- A tablet that types those seven digits gets entry `remote` and takes the role without a question (`enter()` → `takeRole` at once). It then shows the teacher's view with the key marked. The teacher's phone, back with its old token or typing the code, is told "This quiz already has a screen for the class and one that steers" (probe 1, third step).
- The owner accepts that a pupil may read the code off a wall. What is new is where it stands, at the moment the Remote is likeliest away, in the same kind of digits a child is told to type, and that nothing takes the Remote back: "a present tab is never pushed aside". The wall's ⋯ ⇄ Swap puts the class's wall on the child's tablet and the steering view, key included, on the projector.
- Cheap options: show the code only in the sheet behind ⋯ or "A second device ›", as at rest, and in the bar only "Remote gone"; and let the uploading device's secret replace a tab, which fits #4 too.

**3. "Nobody in yet?" after Again (verified).**
- `nobodyYet` (`screen.ts:257`) starts its 90 s when the class code first shows with no players and never again; it returns early while players are in, so the start is as old as the first lobby. "Again with another class" opens an empty lobby with the same code (backlog v4 item 3 removes it only in delivery B), so the wall says at once: "Nobody in yet? If the tablets can't open … the school network may block it". Probe 3: one student, 95 s, a run to the end, Again.
- Fix: start the count again for each class (the run's start, or when the lobby empties).
- Smaller: the line also shows 90 s after the code goes up in an ordinary lesson where the tablets are still being handed out. It is muted and says "may", but it names the network to a class that is watching.

**4. Dead time after the steering tab closes (verified).**
- A Remote phone's tab is closed or killed (sessionStorage and the token go with it), and its owner types the teacher code or taps Resume at once. `there()` counts a silent tab as there for 45 s (`:634`), so entry is `full`: "This quiz already has a screen for the class and one that steers", with a "Try again" that does nothing for about 50 s (probe 4: `/teach` at +51 s). Meanwhile the wall doesn't steer either, since the Remote still counts as present; only the clicker keys work.
- The old choice screen had a "quiet: frees up soon" state (`QUIET_MS` still exists). The new message is false from where the teacher stands and gives no hint.
- The uploading device holds the quiz's secret and is exempt from the digits, but not from `full`. If the secret may replace a tab, this case goes, and #2 too when the teacher's device is the one that uploaded. At least say "if that was you a moment ago, it frees up within a minute".

**5. "Back to the quiz ▶" with the quiz's own tab still open asks the question (verified).**
- A teacher opens the site in a second tab; the landing's resume card is the first thing there; Back to the quiz lands on "Show the quiz here / Steer it from here", and either answer turns the original tab into the other role (probe 1, first step). It is the single-tab case working as designed, but the device that uploaded the quiz is the one that gets it.

**Landing, step 1, the own-copy line, the translations**
- **Step 1.** "Choose any good AI." then "Claude Opus wrote the example quiz, 3 Nov 2026." keeps the owner's rule: true, dated, no claim about tiers. Two things next to it. The example ask is "with photos of two pages", and the backlog (v4 item 16, third look) notes that ChatGPT currently breaks with two attachments; the page sends the likeliest "any good AI" into that without a word, and the only AI named is one most teachers won't use. And the Opus run was the harness with the page injected, not claude.ai fetching it (decisions.md says so); the sentence doesn't claim otherwise.
- **The own-copy line is aimed at the rarer failure.**
  - It appears on a device that has uploaded, when the budget refused an upload on a day of the last 30. `limits.ts:34-37` says the account's allowance covers about 30 classes a day when tablets poll and about 75 on stored rows, "below MAX_UPLOADS_PER_DAY" (300). So the allowance runs out long before the cap, and the days the site really fails are the ones the line cannot know about: the budget can't write then. The decision entry says "understates". I'd say it will almost never show for real use, and show after a script has filled 300 uploads.
  - "New quizzes had to wait for the next day" is true for the upload cap, not for the bytes cap, which clears only as quizzes expire, up to 48 hours.
  - Its link, `/own-copy`, needs an AI that runs programs on a computer one may install on, which the page itself says a school laptop often isn't. For the teacher the line speaks to, "how ›" promises more than that.
- **Translations** (no native check was possible on this side, as disclosed). The forms of address are consistent within each language: du in German, vous in French, tu in Italian, the asks inside the bubbles in the informal form because they are said to an AI; "für dich oder deine Schule gehört euch allein" and "per te o per la tua scuola è solo vostra" change number on purpose and read fine. German is clean ("neue Quiz", the plural without an ending, is the standard one). Nits, none blocking:
  - French "a été plein" for a site would be "complet", and "il remarche" is colloquial; there are no non-breaking spaces before ":" and "?" (the ask's " ? " can start a line);
  - Italian "non è riuscito a prendere il quiz" is stilted ("accettare");
  - "any" is gone from step 1 in all three; French writes CM2 for 5th grade where a Swiss-French teacher says 7H.
- **Student notice.** "This device can't reach the quiz. Tell your teacher." is English-only, for children the product assumes may not read English. A tablet that fell asleep after 45 minutes (`Line.sleep` sets the status offline) shows it too, though it merely sleeps.

**What a stranger could do**
- #1 is the finding. Besides it:
  - `GET /api/site` is one more public call that costs a Function request and a Durable Object request; `/api/stats` and `/api/attempt` are the same kind, and were out of scope before.
  - `/api/join` still answers "no such quiz" against "wrong teacher digits", so live class codes can be told from dead ones, as they could before.
- Checked and sound:
  - `x-cq-ip` can't be set by a client. The Function builds the headers of a POST itself (`[[path]].ts`, `toInstance`) and the instance reads it only on a POST command.
  - The digits are compared in constant time; the secret is exempt and never shown.
  - A wrong guess writes nothing.
  - Counting only two-digit guesses leaves no way to match without being counted.
- If `cf-connecting-ip` doesn't reach the instance in production, every device shares the key "quiz", and five wrong codes from anyone lock everyone out of teacher codes for ten minutes (the uploading device excepted). Not established, see below.

**What holds up**
- **The swap op.** Both tabs get fresh tokens; `evict` reaches live sockets and held polls, and the `moved` map covers a tab between polls. A doubled tap changes nothing the second time (the sender's attachment is cleared, a polling sender is answered with `moved`), and a swap racing a swap ends consistent. A swap needs the other tab to be there, and does not need the wall to steer.
- **`takeRole` and `entry`.** Two devices at once: the loser gets "changed" and then `full` (probe 1, no stale redraw: I expected one from the ack/choose order and didn't find it). `entry()`, `takeRole()` and `enter()` agree with each other and with the table in §4.
- **The BUDGET binding.** The Pages `wrangler.toml` entry matches the state Worker's name, class and script; `Env` has it; the Function calls only `fullDays()`. The `SiteBudget` migration (v4) was already in 61e8db0, so the deploy has no migration and `deploy.mjs` deploys the Worker first. `pages dev` read the binding and answered `{"full":0}`.
- **Keys.** No key starts the quiz from the lobby; Ctrl, Alt and Cmd are excluded; with a Remote only the clicker keys move on.
- **Pages for a first-timer.** Upload through the file input to the check, "Show the class the code", the join screen, Start; no page errors in probe 1 (the others didn't collect them). The guidance's limits (120 pictures, 16 MB, 1600/1920/1200 px, 48 hours, one hour, three hours) match `protocol.ts` and `instance.ts`.
- **Costs.** The strip's images are static files, which the request allowance doesn't count; the landing's calls (`/info`, `/api/site`) are one request each, only from a device that has uploaded.
