**Fix before or right after the first deploy**

1. **Backlog v1 item 2 is not implemented: upload attempts are not counted by format.** The backlog changed in the last commit, after the build, so this is a gap rather than a miss by the implementer.
   - Nothing counts uploads by format anywhere in `src/`.
   - The client never sends a format to the server.
   - An unsupported file (tar.gz, docx, pdf) is read as text and ends with the generic "No questions were found". The teacher is not told that only zip works.
   - The counter itself must hold no content or identity, so a Durable Object counter or Analytics Engine would fit.

2. **The teacher's screen redraws on every student answer, so taps get lost.** In `client/teach.ts`, `render()` replaces `main.innerHTML` and the bottom action bar (Reveal/Next) unconditionally on every server view. Every answer from any student bumps the view, so a class of 25 causes about 25 redraws in a few seconds.
   - A tap that straddles a redraw lands on a node that was just replaced, and the click is probably lost. This is my reading of browser behaviour and I did not test it.
   - It hits exactly when the teacher wants to press Reveal, while answers are still arriving.
   - `play.ts` already avoids this by redrawing only when the student's own view changes. The teacher page has no such guard.
   - The fix is cheap: skip the redraw when the view is unchanged apart from the answered count, and update the counter in place.

**Worth fixing, not blocking**

3. **"Dead device" detection depends on the socket closing at the edge.** Pings are answered by `setWebSocketAutoResponse`, so the Durable Object never sees them.
   - A tablet that dies or sleeps stays "connected" until Cloudflare closes the socket. I could not measure how long that takes.
   - Until then its avatar is not offered in the rejoin chooser, and the teacher sees it as present.
   - The simulation kills devices cleanly, so it does not test this.
   - `ctx.getWebSocketAutoResponseTimestamp(ws)` would let the server mark a socket stale after about 45 s.

4. **A retried `newPlayer` creates a second avatar.**
   - Confirmed by probe: the same command id sent twice over HTTP gave two players.
   - The same can happen over WebSocket if the ack is lost and the socket reconnects.
   - This contradicts the decision "everything a device sends is safe to repeat".
   - The cost is a ghost avatar at 0 points, which the teacher can remove. Keying `newPlayer` on the command id would fix it.

5. **WebSocket fallback only covers sockets that never open** (`client/net.ts`).
   - `wsFailures` resets whenever a socket opens.
   - A school proxy that allows the upgrade but drops frames gives an endless open, no pong, reconnect loop and never switches to long-poll.
   - `/check` has the same blind spot: its echo test would pass on such a network.

6. **The QR code points at `/#code`.** That loads the full guidance page plus `home.js` and then redirects. Pointing it straight at `/play#code` saves a page load on the step the owner calls the slowest.

**Smaller observations**
- `index.html`, the `INSTANCE_IDLE_MS` text and the guidance wording all agree with each other and with the code.
- Join codes and pairing codes have no rate limit. The decisions record this as v2 hardening. A script can guess 5-digit codes at about 160 ms each. A guess that hits a live class joins it and sees questions as they come up. I probed 300 random codes and hit none.
- The site function (the Pages part) has no explicit observability setting. Only the state Worker has `observability = false`. The "no logs, no IPs" claim is therefore unverified for the function that sees every upload. Setting it explicitly is cheap.
- The comment in `functions/api/[[path]].ts` refers to `functions/_routes.json`, which does not exist. Pages should auto-generate `/api/*`, which the Free-plan budget depends on. Confirm in the dashboard after the first deploy.
- `play.css` uses `100vh` for the student layout. If a tablet's Chrome counts the toolbar as part of the viewport, the bottom answer row may need scrolling. This needs a real tablet, or switching to `dvh`.
- A zip is decompressed in the teacher's browser with no size cap. It only affects the teacher's own device.
- The README says Node 22 or newer. `npm test` runs `.ts` files directly, which needs a recent 22.x or newer, so an early 22 would fail the tests. Deploy is unaffected.
- `npm run dev` start order: in my run the site could not reach the state Worker. It returned "Network connection lost" persistently until I started the state Worker first and the site afterwards. That is probably a race in `scripts/dev.mjs`, which starts both at once. It matters for the README's "try it on your own computer" path, not for production.
- The pairing endpoints can be called without limit, so anyone can create a code or pairing record. Same v2 hardening bucket.

**Verified good**
- **No key leak.**
  - Student and projector views carry no key before the reveal. I read them from the live API during a question.
  - A student sending teacher commands gets "not allowed".
  - A bad teacher secret gets "gone".
- **XSS.** All quiz text is escaped in the clients, including a `<script>` payload in the title and answers. I found no unescaped path in `innerHTML` use.
- **Answers.**
  - Bad `choice` or `q` values are rejected.
  - Retries and late answers behave as designed.
  - Scores are computed from answers plus fixes, so changing a key after the reveal moves the points. Speed scoring only needs the `ms` already recorded.
- **Pairing.**
  - Screen and teacher pairing work end to end.
  - A code is single use.
  - Seeing a code grants nothing.
- **Request size and lifetime.**
  - A 2 MB command gets 413 and an oversize quiz gets 400.
  - `endInstance` makes the quiz unreachable immediately.
  - The 48 h idle expiry and the 1 h run expiry are wired to Durable Object alarms. I read that code but did not wait out an alarm.
- **Parser.** It is solid on what AIs actually do. Fences, prose around the quiz, checkboxes, RTL text, two quizzes in one paste and the rendered-chat case (lost markers) are all handled or fail loudly. Negative numbers and several right answers work.
- **Repo hygiene.**
  - `secrets/` is ignored except its README.
  - The git history contains no tokens.
  - `.tmp/` is ignored.
  - `dist/` is ignored.
