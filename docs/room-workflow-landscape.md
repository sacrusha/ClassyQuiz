# The room workflow against quiz tools in common use

2026-11-02. Scope: running a quiz in the room (joining, pacing, reveal, ranking, teacher controls, projector, misbehaving devices and network). Not authoring. Not a survey: seven tools picked for how differently they approach the room. Written for the owner; nothing here is decided, the list at the end is requirements to look out for.

Evidence tags: **[F]** text of the vendor's help page, fetched; **[S]** a search tool's summary of an official page I could not open (Kahoot, Blooket and Quizlet support sites answer 403 to the fetcher and to curl; I did not work around that); **[C]** read in our code; **[M]** my background knowledge, not checked this session. Anything untagged below is our own reasoning. Most vendor pages are undated; Wayground is Quizizz under its new name.

## The tools, by approach

| Tool | Approach to the room | What bears on us |
|---|---|---|
| **Kahoot** | Host-paced game show on a timer. PIN or QR, nickname (optional generator), no account. | Points drop with response time (about 1000 at the fastest, halved at the buzzer), 5 s to 4 min per question [S]. Newer live "Accuracy" experience scores correctness only; "Professional/Lecture" experiences leave the scoreboard to the host [S]. In the classic experience the per-question ranking and the correct answer cannot be switched off; top 5 shown, a player below 5th sees only their score [S]. Host can kick a nickname from the lobby and lock the game against late joiners [S]. Players see only shapes unless the host turns on "show questions and answers" on their devices [S]. Rejoin keeps the score only if the device reconnects by itself or the student picks "Resume as <nickname>"; a manual refresh re-enters with 0 points; in team games rejoin is not possible [S]. Spam bots that join by PIN with offensive names are a known classroom problem; sources are weak (one trade article, the rest content farms) [S]. |
| **Wayground (Quizizz)** | Same content, two pacings: teacher-led, or student-paced with several modes (classic with live leaderboard, mastery loop, team, test). A live session code lasts a few hours; an assigned one lasts to the deadline [F]. | Teacher-led keeps the class on one question [F]. A teacher can switch a running session between the two paces [S, third-party]. **Paper Mode**: questions projected, each student holds a personal QR card, the teacher scans with the phone app, so not everyone needs a device [F]. |
| **Plickers** | No student devices at all. Paper cards with a code whose orientation is the answer; the teacher's phone camera scans the room. | The projected screen can list students while scanning so each sees when their answer is logged "and so they'll know when to lower their card". After scanning, the teacher reveals **the correct answer and the answer spread as two separate steps, in either order**, or skips both. Individual responses can be hidden so students don't copy [F]. Works offline, syncs later [S]. |
| **Socrative** | Teacher-paced or student-paced formative quizzes, no game by default; Space Race as the competitive mode. Room name plus the student's own name (or ID in a rostered room). | **Pause**: students cannot submit while paused, timers stop; recommended before showing results so nobody answers after seeing the key [F]. Instant feedback on the student's device with the teacher's explanation [F]. A student who closes the tab rejoins with the same name and resumes [F]. A June 2026 release note fixes teacher-paced students jumping back to question 1 after a restart [S]: restart recovery is a bug class other tools had to fix in production. |
| **Mentimeter** | Presenter-paced quiz slides inside a presentation. Join code at menti.com, avatar plus nickname. | Pace of a quiz cannot be changed; the presenter always leads. Results and key appear when the countdown ends **or everyone has voted**. The phone shows right or wrong. Leaderboard (top 10) optional per slide: after every question, only at the end, or both. The device is remembered, so a reconnect returns the same avatar and nickname; scoring is per device, so a team can share one device. The one documented failure is a firewall blocking the quiz WebSocket [F]. |
| **Quizlet Live** | Team collaboration: each teammate's screen holds a different piece, so the team must talk. | Quizlet's own posts describe a wrong answer resetting the team's progress; I could not confirm the current rule [S]. Needs four or more players and a set of at least six terms [S]. The design makes the class talk to each other, not look at tablets. |
| **Blooket / Gimkit** | Game layer on top of the questions: modes with their own rules, mostly student-paced; solo or teams. | Host settings that recur: late joining on/off (Blooket: on by default), random names on/off [S]; Gimkit nickname generator, kick in the lobby, host panel with volume, leaderboard, player list, end game [F]. QR on hover over the game code [F]. |

## Where classyQuiz stands

**Matches** what a teacher who knows Kahoot expects: code or QR with no account, host-driven start/reveal/next, colour-and-shape answers, an answered counter, removing a stray player, top-three ranking, keyboard or clicker on the projector (Mentimeter has Enter too [F]), correctness-only scoring (Kahoot now offers it as an experience [S]).

**Beats**, on what I could compare:
- Coming back: a reload, sleep or dropped connection resumes the same avatar and score with no action [C]; Kahoot loses the score on a manual refresh [S], Mentimeter and Socrative resume by device or name [F]. A dead tablet's avatar can be reclaimed [C]; I found no equivalent elsewhere.
- Network: a measured WebSocket-to-long-poll fallback and a `/check` page [C]. Mentimeter documents only "your firewall blocks the WebSocket" [F].
- Fixing the key during the run with the points following, including several right answers [C]. I did not find this in the help pages I could reach; absence is not established, since Kahoot's and Blooket's pages were closed to me.
- Ranking pressure: optional and top three, with ties shared [C]. Kahoot's classic per-question ranking cannot be turned off [S]. Evidence that rankings hurt low performers is mixed and mostly higher-education: a dental-hygiene pilot had 24% finding the live leaderboard stressful, a Kahoot-hosted biology study found anxiety not related to grades. Treat as a reason to keep it optional, not as proof.
- Nothing about a child on the wire: no name, no account. Only Mentimeter comes close (avatar plus a nickname the student types) [F].

**Trails**, in the order the owner is likely to notice:
1. No control over who joins: no lock, no cap, late joiners always accepted, a 5-digit code with no rate limit [C]. Kahoot and Gimkit and Blooket all have a late-join switch or lock.
2. No separate spread: the teacher sees only "n / players answered" while the question is up; the spread appears together with the key at the reveal [C]. Plickers splits the two.
3. `answered / players` counts away devices in the denominator [C], so a dead tablet keeps it below full for the rest of the run.
4. No sound or music. Gimkit puts volume in the host panel [F]; Kahoot's music is from memory [M].
5. No timer, no speed points (v2, planned). No student-paced option (a difference of stance, not a gap: the backlog wants the teacher to set the tempo).
6. No per-student view for the teacher and no end-of-run report. The first is deliberate ("nothing identified"); the report is a Later item.

## Requirements to look out for

Ordered by how much a teacher in the room would feel it. Cost is my guess from reading the code.

1. **Close the door.** The teacher can stop new joins (lobby lock, or "no late joining") and the site has a cap on players per run. Solves: a stray tablet or a child who guessed a code. It also protects the shared free plan, since the code space is 90,000 and a single curious child in a loop could spend a day's request budget for every teacher. Today's stray-avatar removal is the aftermath, not the prevention. Overlaps v2 item 4 (hardening) but the lock is a classroom control, not an abuse control. Cost: small.
2. **Spread, then key.** Two reveal steps, spread first, key second, in either order (Plickers [F]). The teacher may also see the live spread privately while the question is up. Solves: the teaching moment the backlog asks for. "Fifteen of you said the blue one. Turn to your neighbour." Then the key. It also gives the teacher the information to decide whether the question is broken before revealing, which is when item 9's fixes are cheapest. Cost: small to medium; the phase machine has no step between question and reveal.
3. **Who has not answered, without names.** Mark each avatar on the projector once its answer is in, and count only devices that are present in the denominator, showing away ones separately. Solves: the child who wonders whether their tap counted (item 15 for the projector), and the teacher who waits for the last tablet and cannot tell a slow reader from a dead battery. Plickers does the first with a student list [F]; Mentimeter ends the question when everyone has voted [F], which for us could be a cue on the teacher's reveal button, not an automatic step. Cost: small.
4. **Pairs and teams.** Several tools score per device so two children can share one [F], and Kahoot, Blooket, Wayground and Quizlet Live have team modes [S, F]. Our one-avatar-per-device already supports pairs; what is unchecked is whether "of 25" and the ranking read sensibly when 12 tablets stand for 24 children, and whether a teacher would want avatars grouped into teams for the ranking. Teams lower individual exposure, which fits the constraints. Cost: nothing for pairs; teams are a feature.
5. **Test: redeploy and restart during a run.** Socrative had to fix students jumping back to question 1 after a restart [S]. Ours should be safe by design (views from stored state [C]) but the decisions file records no test of a deploy or Durable Object eviction in the middle of a lesson, which is when a teacher-owner who is also the maintainer might push a fix. Cost: one run of the simulator with a deploy in the middle.
6. **Sound, off by default.** A cheerful sound on reveal and final changes the room's energy for classes that want it (v2 neighbours: countdown, speed). It needs a mute on the projector, since school laptops are often at full volume. Low.
7. **Record, do not build: no devices.** Wayground's Paper Mode and Plickers answer "not every lesson has devices" with printed cards and the teacher's camera [F]. The owner said no degraded mode; the backlog's Later "Printables" is the nearest item. Noted so the option is known.
8. **Record, do not build: student-paced.** Wayground, Blooket and Gimkit let each student run at their own speed, and Wayground can switch live [S]. It solves waiting for slow readers, but it removes the shared question on the projector, which is the product. Keep as a stance.

## What I could not establish

- Kahoot's and Blooket's own help pages (403): every Kahoot and Blooket statement is a search summary of the official page; the Kahoot point formula and the "cannot disable ranking" statement deserve one look in a browser before anyone relies on them.
- What Kahoot's host screen offers mid-question (skip, end early) and whether any tool lets a teacher correct a key during a live run.
- Quizlet Live's current rules.
- Gimkit's and Blooket's mode rules; I treated them as a type, not as products.
- Whether teachers actually miss any of the "trails" above. That is a question for the real lesson, not for a help page.
- I did not use the live site: the findings above came from the code, and nothing needed a request.
